## How each approach works

- **READ COMMITTED:** Reads the balance, checks it, then acts. Nothing stops two bets reading the same balance before either writes.
- **SERIALIZABLE:** The same code at the strictest isolation level. Every read keeps a shared lock until COMMIT; deadlocks are retried.
- **UPDLOCK, HOLDLOCK:** Locks the wallet's balance while reading it. Other bets queue until the holder commits.
- **rowversion + retry:** Reads without locking, then updates only if the row's version is unchanged; otherwise reads again and retries.
- **dbo.usp_PostTransaction:** The procedure the API runs, called through SqlLedger exactly as the API calls it, deadlock retries included.
